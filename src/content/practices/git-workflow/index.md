Две ветки: в **`dev`** идёт вся работа, в **`main`** — только версии. Версия — слияние `dev` в `main` с `--no-ff`
и тегом. Так `main` читается как список выпусков, а вся работа видна внутри каждого слияния.

```
dev   ──●──●──●──●──●──●──●──●──●──
         \           \           \
main  ●───●v2026.001──●v2026.002──●v2026.003
```

## Номер версии

`v<год>.<номер>`: год выпуска и номер по порядку в этом году, три цифры — `v2026.001`, `v2026.002`, … С нового
года — снова с `001` (`v2027.001`). Номер ничего не говорит о размере изменений: это просто «какой по счёту выпуск».
Всегда три цифры — чтобы при любом темпе теги сортировались как строки. Тег — аннотированный (`git tag -a`),
сообщение слияния и тега — сам номер.

Тег стоит **на коммите слияния в `main`**, не на коммите в `dev`: версия — ровно то, что попало в `main`, и тег
без слияния не поставить.

## Обычная работа

- Всё — в `dev`: коммиты, правки, эксперименты. В `main` напрямую не коммитить никогда.
- Перед выпуском в `dev` всё должно быть зелёным: все проверки, какие есть в проекте (типы, линтер, тесты).

## Выпустить версию

1. В `dev` чисто, проверки прошли.
2. Номер: последний тег этого года + 1, или `001`, если тегов в этом году нет.
3. Слить и поставить тег:

```sh
git switch main
git merge --no-ff dev -m v2026.004   # всегда слияние, даже если можно было бы перемотать
git tag -a v2026.004 -m v2026.004
git switch dev                       # работа продолжается в dev
```

С удалённым репозиторием — отправить обе ветки и тег: `git push origin main dev v2026.004`.

`main` обратно в `dev` сливать не нужно: в `main` нет ничего, кроме слияний из `dev`, следующее слияние пройдёт без
конфликтов.

## Исправление в выпущенной версии

Отдельных веток для исправлений нет, срочных правок прямо в `main` — тоже: исправить в `dev`, проверить и сразу
выпустить следующую версию. Откатить сайт — выложить предыдущий тег.

## Правила

- В `main` — только слияния `--no-ff` из `dev` с тегом версии. Никаких прямых коммитов, перемотки и `rebase`.
  Исключение — первый коммит репозитория, от которого начинается `dev`.
- Тег не переносить и не удалять после того, как он ушёл наружу (выложен или отправлен в удалённый репозиторий).
- Выкладывается всегда тег, а не «последний `main`»: версия на сервере = тег.
- Выпуск — только по просьбе человека; `push` — после отдельного подтверждения: это уходит наружу.

## Проверка

Репозиторий соответствует, если:

- `git log --first-parent main` — первый коммит и дальше только слияния (у каждого два родителя), второй родитель
  каждого — из `dev`;
- на каждом слиянии в `main` ровно один тег, аннотированный, вида `v\d{4}\.\d{3}`, и тег совпадает с сообщением;
- номера внутри года идут подряд с `001`, без пропусков и повторов.
