Дополнение к практике: связанные с ней материалы — примеры, пояснения, инструменты. Может пригодиться, а может оказаться лишним: соответствие проверяется только по самой практике.

## Инструменты

- **Playwright Test**, виды — проекты Playwright: `server`, `ui`, `e2e`.
- Тестовая сборка Nuxt — в `.nuxt-test` и `.output-test`; скрипт запуска пересобирает её, только если исходники
  новее.
- Настройки — `.env.autotest` и `.env.autotest.e2e`: по ним запускаются серверы, их же читают проверки.
- База — PGlite, своя папка на вид проверок, каждый прогон с нуля.

## Поддомены без файла hosts

Chromium направляет `*.<проект>.test` на эту машину флагом `--host-resolver-rules` в `playwright.config.ts`.
Приложение выдаёт cookie на `.<проект>.test` — как на боевом домене.

## Данные и время

- Метка (`stamp()`) в почте и логине — у каждой проверки свои записи.
- `POST /_test/cleanup { now, … }` — уборка «как будто сейчас `now`» только для своих записей.
- У каждого «браузера» свой адрес в `X-Forwarded-For` — лимиты по адресу не срабатывают на всех сразу.

## Тестовые ручки

Все — при `TEST_HOOKS=on`: `/_test/mail?to=<почта>` (коды из писем), `/_test/cleanup`, капча по заголовку
`x-test-captcha: 1` с токеном `test-pass`. Встроенные лимиты библиотеки входа в проверках выключены, свои лимиты
работают.

## Экраны

Ширина телефона — 375 px. Помощники: `watchConsole` (ошибка консоли — провал), `expectNoHorizontalScroll`.

## Что проверяю руками

Вход через Google, живой виджет Turnstile (тестовые ключи), настоящая почта, `Secure`-cookie на https, лимиты
библиотеки входа (включены только в production), уборка по расписанию.
