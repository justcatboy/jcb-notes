На моих примерах: как я выполняю этот стандарт в своих проектах и на своих технологиях. Не требование — соответствие проверяется только по стандарту.

## Образ

`Dockerfile` в два этапа:

1. сборка: `npm ci --ignore-scripts` → `npm run build`;
2. запуск: только `.output`, `USER node`, `node .output/server/index.mjs`.

`.dockerignore` — `.env*`, `.nuxt*`, `.output*`, `.data/`, результаты Playwright, `.git`. Шрифты скачиваются при
сборке — сборке нужен интернет.

## Миграции и здоровье

- Миграции Drizzle лежат в репозитории, кладутся в сборку и применяются при старте.
- `GET /_health` → `{ status: 'ok', version, db: 'ok' }` или 503.
- Уборка — задача Nitro по расписанию; лимиты в памяти процесса, поэтому экземпляр один.

## Обвязка

- `docker-compose.yml`: приложение на `127.0.0.1:<порт>`, PostgreSQL без публикации порта, тома, проверки
  здоровья, лимит размера логов.
- CI — GitHub Actions: проверки на каждый push, образ на тег версии — в GHCR.
- `deploy/update.sh` — выкатить или откатить версию по тегу.
- Прокси, файрвол и адреса машины — в личной заметке вне git.

## Списки

Лежат в `docs/deploy.md` проекта. После выкладки проверяю:

- `GET /_health` — 200;
- регистрация на настоящую почту — письмо пришло;
- cookie сессии с `Secure; HttpOnly` и нужным `Domain`;
- вход через Google, виджет капчи — если ключи заданы;
- админка у обычного человека — «Нет доступа», документация API и `/_test/*` — 404.
