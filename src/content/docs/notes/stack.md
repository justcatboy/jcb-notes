Не стандарт, а то, на чём я пишу сейчас. Многие стандарты здесь выросли из этого стека — читать их стоит с этой
поправкой.

## Стек

- **Nuxt 4 + Nuxt UI 4 + Tailwind CSS 4**, сервер — Nitro внутри Nuxt.
- **Drizzle + PostgreSQL.** При разработке и в проверках — PGlite как сетевой сервер на своём порту: одну папку
  PGlite не открыть двумя процессами. Он ведёт себя не во всём как PostgreSQL (параллельные транзакции не
  воспроизводятся), поэтому перед выкладкой я запускаю боевой образ с настоящим PostgreSQL.
- **Playwright Test** — все проверки.
- **Windows, PowerShell 7, Node 26**: скрипты `.ts` запускаю напрямую.

## Как я пишу

- Быстро меняющиеся библиотеки (например, better-auth) — версия закреплена точно, без `^`; обновляю с прогоном всех
  проверок.
- Интерфейс, документы и комментарии — по-русски; коммиты — по-английски (`feat:`, `fix:`, `docs:`).
- Ошибки для человека — свои тексты; незнакомую ошибку библиотеки не показываю как есть.
- База: snake_case, в коде camelCase; время — `timestamptz`; id — UUID от сервера; наружу — только публичный id.
- Миграции генерирую по схеме и коммичу вместе с ней.
- Запись, порядок которой важен другим (журнал событий), — под блокировкой в той же транзакции.
- `server/utils` в Nuxt автоимпортируется — одно имя не экспортирую из двух файлов.
- При старте разработки — короткая сводка в консоли: адреса, база, что включено.
