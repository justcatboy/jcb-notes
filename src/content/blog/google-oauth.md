Клиент OAuth в Google Cloud для кнопки «Войти через Google». Подходит для любой библиотеки авторизации, где вход идёт
через сервер (обмен кодом на сервере).

## Завести клиента

[Google Cloud Console](https://console.cloud.google.com/) → свой проект → **Google Auth Platform** (раньше —
«APIs & Services → OAuth consent screen»):

1. **Branding** — название приложения, почта поддержки, свой домен в Authorized domains, ссылки на главную, политику
   конфиденциальности и условия (без них не опубликовать).
2. **Audience** — **External**. В статусе **Testing** войти могут только «Test users» (до 100). Для всех — **Publish
   app**. Области `openid email profile` не «чувствительные»: проверка Google не нужна (кроме проверки бренда, если
   загружен логотип).
3. **Clients** → Create client → **Web application**:
   - **Authorized redirect URIs** — адрес возврата твоей библиотеки, например `https://example.com/api/auth/callback/google`;
   - **Authorized JavaScript origins** — не нужны, если обмен кодом идёт на сервере.
4. Client ID и Client secret — в переменные окружения сервера. Секрет — не в git.

Для разработки — **отдельный клиент** в Testing с `http://localhost:<порт>/…` в redirect URI и собой в Test users:
так `localhost` не висит в боевом клиенте.

## Что брать у Google

Достаточно почты и признака «почта подтверждена». Имя и фото можно не брать: меньше данных — меньше вопросов.

`prompt: 'select_account'` — Google каждый раз спрашивает, каким аккаунтом войти; без него молча входит последним.

## Аккаунт с той же почтой уже есть

Привязывать вход через Google к существующему аккаунту автоматически — **только для `gmail.com` и
`googlemail.com`**: там ящик и Google-аккаунт — одно и то же. Google-аккаунт можно завести на любую чужую почту, и
адрес мог давно перейти к другому человеку. Для остальных доменов — ошибка «войдите паролем и привяжите Google в
настройках».
