# JCB-NOTES

Личный блог о разном — от разработки до всего, что интересно, — гайды и стандарты `jcb-*` для своих проектов:
ветки и версии, настройки окружения, порты, проверки, выкладка и внешние службы. Сайт собирается на
[Astro](https://astro.build/), оформление своё.

**Сайт:** https://jcb-notes.pages.dev/ — обновляется с каждой версией (слияние в `main`): Cloudflare Pages
собирает и выкладывает его сам.

## Что здесь

| Что | Где | Как меняется |
|---|---|---|
| **Блог** — заметки и гайды; гайд — пост с меткой `гайд`: как сделать конкретное дело, по шагам | `src/content/blog/<slug>.md` | свободно; заметно поправили — поле `updated` |
| **Стандарты** `jcb-*` — правила, по которым можно сказать «проект соответствует / не соответствует» | `src/content/standards/<имя>/index.md` | редко, с версией и записью в «Истории» |
| **Приложение** к стандарту — необязательное дополнение: связанные материалы (примеры, пояснения, инструменты), которые могут пригодиться | `src/content/standards/<имя>/appendix-<N>.md` | свободно, без новой версии стандарта |
| **Страницы** вне блога — сейчас «Мой стек» (`/stack/`) | `src/content/pages/<имя>.md` | свободно |

Главная — о чём сайт, три последние записи и стандарты, справа — календарь с днями записей и шуточная «реклама»;
полная лента — `/blog/`. Справа у каждой страницы своя колонка: оглавление статьи, метки, файлы для Claude; на узком экране она уходит под текст, а оглавление сворачивается
в «Содержание» над текстом. В шапке — разделы «блог», «стандарты», «стек» и переключатель темы,
в подвале — © с годами, версия сайта (тег из git, `v2026.002`), исходники, лицензия и RSS.
Оформление — `src/styles/site.css`, каркас страниц — `src/layouts/Base.astro`.

## Как пользоваться стандартом

Проект перечисляет принятые стандарты с версиями в своём `CLAUDE.md` или README:

```md
Стандарты: jcb-git-workflow v1.0, jcb-dotenv v1.0, jcb-devports v1.0
```

Стандарты не ссылаются друг на друга — каждый можно взять отдельно. Соответствие проверяется по разделу
«Проверка» стандарта.

## Для Claude и скриптов

Всё собирается при сборке, сервер не нужен:

| Адрес | Что |
|---|---|
| `/llms.txt` | оглавление сайта для LLM ([llmstxt.org](https://llmstxt.org/)): посты, страницы и ссылка на оглавление стандартов |
| `/standards/llms.txt` | оглавление стандартов: как пользоваться и ссылки на `.md` каждого стандарта и приложения |
| `/standards/llms-full.txt` | все стандарты с приложениями одним файлом — текущие версии |
| `/standards/index.json` | стандарты: код, текущая версия, черновик ли, ссылки на текст и приложение, все версии |
| `/standards/<имя>/<версия>.md` | **неизменяемый** текст версии, например `/standards/dotenv/v1.0.md` — на него ссылается проект |
| `/<адрес>.md` | текущий текст любой страницы, например `/standards/dotenv.md`, `/blog/brevo.md` |
| `/rss.xml` | RSS блога |

Старые адреса (`/guides/…`, `/notes/…`, `/standards.json`, `/llms-full.txt`) перенаправляются на новые —
`public/_redirects`, его читает Cloudflare Pages.

Прошлые версии стандартов берутся из истории git: для каждой версии — последний коммит, где она стояла в файле.
Поэтому историю `main` после выпуска не переписывать.

## Версии

`v<старший>.<младший>`:

- правило поменялось по сути (проект может перестать соответствовать) — старший номер (`v2.0`);
- добавилось или уточнилось, не ломая соответствия, — младший (`v1.1`);
- правка опечатки или формулировки без изменения смысла — без новой версии;
- `v0.x` — черновик: может меняться как угодно; первая устоявшаяся версия — `v1.0`.

## Разработка

```sh
npm install
npm run dev       # http://127.0.0.1:3200
npm run build     # сайт в dist/
npm run preview   # собранный сайт: http://127.0.0.1:3201
```

Порты — блок 3200–3209: `+0` — `dev`, `+1` — `preview`.

## Как писать

- Заголовок — в `title` вверху файла, а не `# …` в тексте: сайт сам выводит его заголовком страницы.
- Новый пост — файл в `src/content/blog/`; адрес — по имени файла. В ленту, RSS и `llms.txt` попадает сам.

  ```yaml
  title: 'Почта через Brevo (SMTP)'
  description: 'Почта по SMTP: домен (DKIM, DMARC), отправитель, SMTP-ключ.'   # строка для ленты и RSS
  date: 2026-11-16
  updated: 2026-12-01   # необязательно
  tags: [гайд, почта]
  ```

- Новый стандарт — папка `src/content/standards/<имя>/` с `index.md` (и, если нужно, приложением
  `appendix-1.md`) и имя в `standardGroups`
  в `src/site.ts` (порядок в списке; без этого сборка падает). Шапка стандарта — полями во frontmatter; сайт
  показывает её под заголовком («Стандарт jcb-dotenv - v1.0 - 2026-11-16») и добавляет в скачиваемый `.md`.
  Формат проверяется при сборке.

  ```yaml
  title: 'Настройки только в .env-файлах'
  code: jcb-dotenv
  version: v1.0
  date: 2026-11-16
  ```

- Стандарт не ссылается ни на что вне себя.
- У каждой страницы есть кнопка «Скачать .md»: файл `/<адрес>.md` собирается из страницы, отдельно не ведётся.
- Без персональных данных и секретов. Примеры — `example.com`, `*.test`.
- Репозиторий ведётся по jcb-git-workflow: работа — в `dev`, версии — слияниями в `main` с тегом.
