# JCB-NOTES

Личный блог о разном, гайды и практики `jcb-*` для своих проектов. Сайт на [Astro](https://astro.build/),
оформление своё.

**Сайт:** https://jcb-notes.pages.dev/ — Cloudflare Pages собирает и выкладывает его сам при каждой версии
(слиянии в `main`).

## Что где лежит

| Что | Где |
|---|---|
| **Посты** — заметки и гайды; гайд — пост с меткой `guide` | `src/content/blog/<slug>.md` |
| **Практики** `jcb-*` — правила, по которым проект соответствует или нет | `src/content/practices/<имя>/index.md` |
| **Приложения** к практике — необязательные дополнения: примеры, пояснения, инструменты | `src/content/practices/<имя>/appendix-<N>.md` |
| **Страницы** вне блога — сейчас «Размещение» (`/placement/`) | `src/content/pages/<имя>.md` |
| **Рекламные места** в правой колонке главной — список, сверху вниз | `src/ads.ts` |
| Баннеры: адаптивные SVG (встраиваются в страницу) и картинки | `src/side/<имя>.svg`, `public/side/<имя>.png` |
| Оформление и каркас страниц | `src/styles/site.css`, `src/layouts/Base.astro` |

## Как писать

Заголовок — в `title` вверху файла: сайт сам выводит его заголовком страницы. Формат полей проверяется при сборке.

**Пост** — файл в `src/content/blog/`, адрес — по имени файла. В ленту, RSS и `llms.txt` попадает сам.

```yaml
title: 'Почта через Brevo (SMTP)'
description: 'Почта по SMTP: домен (DKIM, DMARC), отправитель, SMTP-ключ.'   # строка для ленты и RSS
date: 2026-11-16
updated: 2026-12-01   # необязательно: заметно поправили
tags: [guide, email]      # метки — на английском
```

**Практика** — папка `src/content/practices/<имя>/` с `index.md` и имя папки в `practiceGroups` в `src/site.ts`
(без этого сборка падает). Шапка — полями во frontmatter: сайт показывает её под заголовком и добавляет в `.md`.

```yaml
title: 'Настройки в .env-файлах'
code: jcb-dotenv
version: v2.1
date: 2026-11-19
```

- Практика самодостаточна: ссылок на другие документы в нём нет, каждый можно взять отдельно.
- Соответствие проверяется по разделу «Проверка» практики; изменения — в «Истории», новые сверху. Несколько
  изменений в версии — вложенным списком, по пункту на каждое.
- Приложение — `appendix-1.md` рядом с `index.md`; правится свободно, без новой версии практики.

**Версии практик** — `v<старший>.<младший>`:

- правило поменялось по сути и проект может перестать соответствовать — старший номер (`v2.0`);
- добавилось или уточнилось с сохранением соответствия — младший (`v1.1`);
- опечатка или формулировка без изменения смысла — та же версия;
- `v0.x` — в разработке, меняется свободно; на сайте — отдельным списком «В разработке»; первая устоявшаяся версия — `v1.0`.

Проект перечисляет принятые практики с версиями в своём `CLAUDE.md` или README:

```md
Практики: jcb-git-workflow v1.0, jcb-dotenv v2.1 — https://jcb-notes.pages.dev/practices/llms.txt
```

**Рекламное место** — строка в `src/ads.ts`. Требования к баннерам для тех, кто их делает, — страница
[«Размещение»](https://jcb-notes.pages.dev/placement/) (`src/content/pages/placement.md`).

```ts
{ title: 'Здесь могла быть ваша реклама', text: 'закажите прямо сейчас!' },           // текст в пунктирной рамке
{ banner: 'side-practices', href: '/practices/' },                                   // адаптивный SVG из src/side/
{ image: '/side/x.png', imageDark: '/side/x-dark.png', alt: 'Что на баннере', href: 'https://…' }, // картинка
```

В именах файлов и путях баннеров — без `ad`, `ads`, `banner`, `promo`: блокировщики рекламы их скрывают.

**Общее:** без персональных данных и секретов, примеры — `example.com`, `*.test`. Репозиторий ведётся по
jcb-git-workflow: работа — в `dev`, версии — слияниями в `main` с тегом.

## Для Claude и скриптов

Всё собирается при сборке:

| Адрес | Что |
|---|---|
| `/llms.txt` | оглавление сайта ([llmstxt.org](https://llmstxt.org/)): посты, страницы, ссылка на оглавление практик |
| `/practices/llms.txt` | оглавление практик: как пользоваться, ссылки на `.md` практик и приложений; принятые и в разработке — отдельно |
| `/practices/llms-full.txt` | все практики с приложениями одним файлом |
| `/practices/index.json` | практики: код, текущая версия, в разработке ли (`draft`), ссылки на текст, приложения (`appendices`) и все версии |
| `/practices/<имя>/<версия>.md` | **неизменяемый** текст версии, например `/practices/dotenv/v1.0.md` |
| `/<адрес>.md` | текущий текст любой страницы: `/practices/dotenv.md`, `/blog/brevo.md` |
| `/rss.xml` | RSS блога |

Прошлые версии практик берутся из истории git, поэтому историю `main` после выпуска не переписывать.
Старые адреса (`/guides/…`, `/notes/…`, `/standards/…`, `/standards.json`, `/llms-full.txt`) перенаправляет `public/_redirects`.

## Разработка

```sh
npm install
npm run dev       # http://127.0.0.1:3200
npm run build     # сайт в dist/
npm run preview   # собранный сайт: http://127.0.0.1:3201
```

Порты — блок 3200–3209. Как выглядят рекламные места при блокировщике рекламы — http://127.0.0.1:3200/?adblock
(только в `dev`).
