# JCB-NOTES

Личный блог о разном, гайды и стандарты `jcb-*` для своих проектов. Сайт на [Astro](https://astro.build/),
оформление своё.

**Сайт:** https://jcb-notes.pages.dev/ — Cloudflare Pages собирает и выкладывает его сам при каждой версии
(слиянии в `main`).

## Что где лежит

| Что | Где |
|---|---|
| **Посты** — заметки и гайды; гайд — пост с меткой `гайд` | `src/content/blog/<slug>.md` |
| **Стандарты** `jcb-*` — правила, по которым проект соответствует или нет | `src/content/standards/<имя>/index.md` |
| **Приложения** к стандарту — необязательные дополнения: примеры, пояснения, инструменты | `src/content/standards/<имя>/appendix-<N>.md` |
| **Страницы** вне блога — сейчас «Мой стек» (`/stack/`) | `src/content/pages/<имя>.md` |
| **Рекламные места** в правой колонке главной | `src/ads.ts` |
| Оформление и каркас страниц | `src/styles/site.css`, `src/layouts/Base.astro` |

## Как писать

Заголовок — в `title` вверху файла: сайт сам выводит его заголовком страницы. Формат полей проверяется при сборке.

**Пост** — файл в `src/content/blog/`, адрес — по имени файла. В ленту, RSS и `llms.txt` попадает сам.

```yaml
title: 'Почта через Brevo (SMTP)'
description: 'Почта по SMTP: домен (DKIM, DMARC), отправитель, SMTP-ключ.'   # строка для ленты и RSS
date: 2026-11-16
updated: 2026-12-01   # необязательно: заметно поправили
tags: [гайд, почта]
```

**Стандарт** — папка `src/content/standards/<имя>/` с `index.md` и имя папки в `standardGroups` в `src/site.ts`
(без этого сборка падает). Шапка — полями во frontmatter: сайт показывает её под заголовком и добавляет в `.md`.

```yaml
title: 'Настройки только в .env-файлах'
code: jcb-dotenv
version: v1.1
date: 2026-11-18
```

- Стандарт самодостаточен: ссылок на другие документы в нём нет, каждый можно взять отдельно.
- Соответствие проверяется по разделу «Проверка» стандарта; изменения — в «Истории».
- Приложение — `appendix-1.md` рядом с `index.md`; правится свободно, без новой версии стандарта.

**Версии стандартов** — `v<старший>.<младший>`:

- правило поменялось по сути и проект может перестать соответствовать — старший номер (`v2.0`);
- добавилось или уточнилось с сохранением соответствия — младший (`v1.1`);
- опечатка или формулировка без изменения смысла — та же версия;
- `v0.x` — черновик, меняется свободно; первая устоявшаяся версия — `v1.0`.

Проект перечисляет принятые стандарты с версиями в своём `CLAUDE.md` или README:

```md
Стандарты: jcb-git-workflow v1.0, jcb-dotenv v1.1 — https://jcb-notes.pages.dev/standards/llms.txt
```

**Общее:** без персональных данных и секретов, примеры — `example.com`, `*.test`. Репозиторий ведётся по
jcb-git-workflow: работа — в `dev`, версии — слияниями в `main` с тегом.

## Для Claude и скриптов

Всё собирается при сборке:

| Адрес | Что |
|---|---|
| `/llms.txt` | оглавление сайта ([llmstxt.org](https://llmstxt.org/)): посты, страницы, ссылка на оглавление стандартов |
| `/standards/llms.txt` | оглавление стандартов: как пользоваться, ссылки на `.md` стандартов и приложений |
| `/standards/llms-full.txt` | все стандарты с приложениями одним файлом |
| `/standards/index.json` | стандарты: код, текущая версия, черновик ли, ссылки на текст, приложения (`appendices`) и все версии |
| `/standards/<имя>/<версия>.md` | **неизменяемый** текст версии, например `/standards/dotenv/v1.0.md` |
| `/<адрес>.md` | текущий текст любой страницы: `/standards/dotenv.md`, `/blog/brevo.md` |
| `/rss.xml` | RSS блога |

Прошлые версии стандартов берутся из истории git, поэтому историю `main` после выпуска не переписывать.
Старые адреса (`/guides/…`, `/notes/…`, `/standards.json`, `/llms-full.txt`) перенаправляет `public/_redirects`.

## Разработка

```sh
npm install
npm run dev       # http://127.0.0.1:3200
npm run build     # сайт в dist/
npm run preview   # собранный сайт: http://127.0.0.1:3201
```

Порты — блок 3200–3209. Как выглядят рекламные места при блокировщике рекламы — http://127.0.0.1:3200/?adblock
(только в `dev`).
