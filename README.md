# JCB-NOTES

Мои стандарты и гайды для своих проектов: как я веду ветки и версии, настройки окружения, порты, проверки,
выкладку и внешние службы. Сайт собирается на [Astro Starlight](https://starlight.astro.build/).

**Сайт:** https://justcatboy.github.io/jcb-notes/ — обновляется с каждой версией (слияние в `main`).

## Что здесь

| Что | Где | Как меняется |
|---|---|---|
| **Стандарты** `jcb-*` — правила, по которым можно сказать «проект соответствует / не соответствует» | `src/content/docs/standards/<имя>/index.md` | редко, с версией и записью в «Истории» |
| **Приложение 1** к стандарту — как я выполняю его на своих примерах и технологиях; ничего не требует | `src/content/docs/standards/<имя>/appendix-1.md` | свободно, без новой версии стандарта |
| **Гайды** — как подключить внешнюю службу, по шагам | `src/content/docs/guides/` | по мере того, как меняются службы |
| **Claude** — как я работаю с агентом | `src/content/docs/claude/` | свободно |
| **Notes** — заметки, сейчас «Мой стек»: на чём я пишу | `src/content/docs/notes/` | свободно |

Разделы — вкладки в шапке сайта (плагин [starlight-sidebar-topics](https://github.com/HiDeoo/starlight-sidebar-topics)),
слева — меню только текущего раздела. В подвале — версия сайта (тег из git, `v2026.002`), исходники и лицензия.

## Как пользоваться стандартом

Проект перечисляет принятые стандарты с версиями в своём `CLAUDE.md` или README:

```md
Стандарты: jcb-git-workflow v1.0, jcb-dotenv v1.0, jcb-devports v1.0
```

Стандарты не ссылаются друг на друга — каждый можно взять отдельно. Соответствие проверяется по разделу
«Проверка» стандарта.

## Версии

`v<старший>.<младший>`:

- правило поменялось по сути (проект может перестать соответствовать) — старший номер (`v2.0`);
- добавилось или уточнилось, не ломая соответствия, — младший (`v1.1`);
- правка опечатки или формулировки без изменения смысла — без новой версии;
- `v0.x` — черновик: может меняться как угодно; первая устоявшаяся версия — `v1.0`.

## Разработка

```sh
npm install
npm run dev       # http://127.0.0.1:3200
npm run build     # сайт в dist/
npm run preview   # собранный сайт: http://127.0.0.1:3201
```

Порты — блок 3200–3209: `+0` — `dev`, `+1` — `preview`.

## Как писать

- Заголовок — в `title` вверху файла, а не `# …` в тексте: Starlight сам выводит его заголовком страницы.
- Новый стандарт — папка `standards/<имя>/` с `index.md` и `appendix-1.md` и имя в списке `standards` в
  `astro.config.mjs`. Гайд, страница Claude или Notes попадает в меню своего раздела сама. На главной
  (`src/content/docs/index.md`) — строка в таблицу.
- Новый раздел — папка в `src/content/docs/` и тема в `starlightSidebarTopics([...])` в `astro.config.mjs`.
- Шапка — полями во frontmatter, не строкой в тексте; сайт показывает её под заголовком («Стандарт jcb-dotenv -
  v1.0 - 2026-11-16») и добавляет в скачиваемый `.md`. Формат проверяется при сборке.

  ```yaml
  code: jcb-dotenv   # только у стандартов
  version: v1.0
  date: 2026-11-16
  ```

- Стандарт не ссылается ни на что вне себя.
- У каждой страницы есть кнопка «Скачать .md»: файл `/<адрес>.md` собирается из страницы, отдельно не ведётся.
- Без персональных данных и секретов. Примеры — `example.com`, `*.test`.
- Репозиторий ведётся по jcb-git-workflow: работа — в `dev`, версии — слияниями в `main` с тегом.
